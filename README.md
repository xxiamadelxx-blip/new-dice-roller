# Ø Dice

Самодостаточный WebGL-роллер D&D-костей от `к4` до одиночного физического по форме `к100`.

## Что уже есть

- настоящая WebGL-сцена без 2D-fallback: лоток, башня и набор полигональных костей;
- `к4`, `к6`, `к8`, `к10`, `к12`, `к20`, `к100`;
- криптографически стойкий равномерный выбор результата через rejection sampling;
- результат выбирается до анимации и не меняется во время броска;
- количество костей 1–8, общий модификатор и модификатор на каждую кость;
- D&D-преимущество/помеха для одиночного `к20`;
- история сессии и копирование результата;
- независимые категории оформления: кости, лоток, башня, фон;
- выбранные косметические наборы сохраняются локально после перезагрузки;
- при недоступном WebGL бросок блокируется и показывается честный error-state без 2D-fallback;
- QA-handshake для Ø Browser:
  - `dice.visual.profile = adel-dice-webgl-v1`;
  - `dice.webgl.status = ready`;
  - `dice.visual.fallback = false`;
  - `dice.visual.phase = settled`;
  - положительный возрастающий `dice.visual.frame_id`.

Референсы Visual Lab переведены в систему материалов: обсидиан/лазурит/кварц/кровавик/опалит для костей, чёрная кожа/резной дуб/кость дракона для лотка, резное дерево/латунь для башни и три окружения — карта, горный перевал и стол при свечах.

## Запуск

Проект не требует сборщика и внешних библиотек. Для корректной работы модулей запустите любой статический сервер из корня:

```bash
python3 -m http.server 4173
```

Затем откройте `http://127.0.0.1:4173/` в браузере с WebGL. Прямое открытие через `file://` не является поддерживаемым режимом ES-модулей.

## Контур Ø Browser / Cloud Stand

Страница не выполняет произвольный JS-запрос от агента. Она только сообщает allowlisted QA-состояние через уже существующий `window.__O_BROWSER_QA__`, если его предоставляет Ø Browser. Аппаратный захват должен вызываться с профилем `adel-dice-webgl-v1` через команду `dice_visual_capture`.

Cloud Stand остаётся отдельной инфраструктурой нативной Android-проверки и не превращается в копию исходников приложения. Для этой WebGL-версии исходной проверкой являются exact-SHA GitHub-состояние, модульные тесты и захват страницы в Ø Browser; нативный APK-тест нужен только после добавления Android-оболочки.
